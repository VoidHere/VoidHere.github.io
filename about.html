About this place

A toolbox with no lock on the door, because there's nothing inside worth locking.

How it actually works

When you drop a file onto one of these tools, nothing is sent anywhere. Your browser reads the file directly from your disk using the same machinery it already uses to display images and play video. The file sits in the page's own memory while a tool works on it, and the result is handed back to you as a fresh download.

That's the entire architecture. No upload, no queue, no "processing…" that depends on someone else's computer. You can prove it yourself: load this site, unplug the network cable, and every tool keeps working. The only thing that ever needs the network is your first visit — after that the browser has it all.

The upside of this design is privacy and reliability. The honest trade-off is speed on the heavy stuff. Video compression and OCR are genuinely hard work, and one processor in a laptop is slower than a rack of server CPUs. For everything else — PDFs, images, text — you won't notice a difference.

Why it exists

I ran into the same wall everyone does: needing to merge two PDFs, and being asked to create an account, accept a cookie banner, and trust a company I'd never heard of with documents I'd never show a stranger. That's a strange deal to accept for a task a browser can do alone.

So this is the version of that site I wanted to find. It runs in Kasur, Pakistan from a single desk, it doesn't want your email, and it will never email you. If it saves you an afternoon, that's the payment it was built for.

What this site will never do

The limits matter as much as the features, so here's the straight list:

  • Never upload your files. There is no upload code anywhere in it, which is why the privacy page is one screen long.
  • Never watermarks your output. A tool that marks your work until you pay isn't a tool, it's a hostage situation.
  • Never asks for an account. There is nothing to log into, so there is nothing to log.
  • Never runs ads or trackers. No analytics scripts, no embedded fonts from other companies, no pixel anything.
  • Never promises layout-perfect Office conversion. PDF → Word with formatting intact is a hard research problem. The text export here is honest about that instead of pretending.

What's under the hood

The tools are assembled from excellent open-source engines, all of them running locally. Credit where it's due:

  • PDF-lib and pdf.js — building and rendering PDFs (Mozilla's renderer, the one in Firefox)
  • ffmpeg.wasm — the video and audio engine, a full ffmpeg compiled to WebAssembly
  • tesseract.js — the OCR engine
  • JSZip, fflate — archives and compression
  • SheetJS — spreadsheets; marked and turndown — Markdown both ways; jsdiff — text comparison
  • piexifjs (metadata), heic2any (iPhone photos), UTIF (TIFF), qrcode-generator, jsQR, JsBarcode

All of these are permissively licensed and shipped with the site — your browser fetches them from this same domain, never from a CDN. One less company learning what tools you use.

Where the honest limits are

  • Password-protected PDFs can't be opened by a browser-based tool. Unlock them first wherever you set the password.
  • Office files to PDF (Word, Excel, PowerPoint in → PDF out) needs a full office engine. The text-only PDF → Word converter is there; the reverse waits for a properly licensed engine.
  • Gigabyte-scale video will hit your machine's memory before it hits any limit of the software. For feature-length footage, a desktop editor is the right tool and this site won't pretend otherwise.
  • Everything is English-only for now — including OCR, which supports one language at a time by design, keeping the download small.

Something missing?

If a tool misbehaves or a task is missing from the toolbox, the contact page has a real address attached to a real person. Feature requests are read, and the honest ones get built.
