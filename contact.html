When to write

  • A tool crashed or produced something wrong. The most valuable mail there is. Include the browser you used, what you were converting, and what happened. If you can attach the file that broke it, it gets fixed faster — and if it's sensitive, describe it instead; that's understood too.
  • A tool did something great. Genuinely useful to hear which ones earn their keep; it steers what gets built next.
  • A tool is missing. If it can run in a browser without a server, it's a candidate. If it can't, you'll get an honest explanation rather than a roadmap promise.
  • Something about privacy or security concerns you. Fair. Ask, and the answer will be direct.

When not to write

  • Requesting uploads or cloud storage. That's the one feature this site is defined by not having.
  • Advertising and sponsorship. There's nothing to sponsor; the tools run on your machine, not on a budget.
  • Bug reports for password-protected PDFs. The limit is real and documented, not a bug.

What happens to your email

It sits in an inbox, gets read, and gets answered. It's not added to a list, not shared, not processed by a helpdesk robot. There is no newsletter — building one would betray the entire premise of this website.
